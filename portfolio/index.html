Latest release

Funding kept private, a spreadsheet that syncs, and top donors

The organization’s statistics lived in one Excel workbook per year. The portal now holds every activity, and three changes made it safe and practical to keep it current.

Drop to sync the statistics workbook

Drop the Excel file, choose this month or this year, and see every change before anything is saved. Empty fields are filled; values that differ from the portal are left for a person to decide; nothing is ever deleted; and the sync is saved all at once or not at all.

  1. Drop the workbook or choose it. One sheet per year is read in the browser.

  2. Pick the period. New activities are listed, each with its row number in the sheet.

  3. Updates show the sheet and portal values side by side. Differences start unticked.

  4. Applied in one transaction. Records the sheet doesn’t list are kept.

In the field

Built for the phone first

Most field staff open the portal on a phone. Every page fits a 390 px screen without sideways scrolling, and it installs like an app that keeps working on a weak signal.

Under the hood

How it is built

Permissions in the database

Row-level security calls one has_permission() check, so changing who can do what is a data change, not new code. Funding lives in its own table that only administrators and coordinators can read.

All-or-nothing sync

A single Postgres function applies the reviewed workbook changes in one transaction and refuses funding changes from anyone without access.

Works offline

A service worker caches the app so it opens without a signal, and field uploads wait on the device until the connection returns.

Tested

227 database checks cover each role’s access; a headless browser checks pages for sideways scrolling, console errors and the motion shown above.
